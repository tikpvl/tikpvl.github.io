СЕМИНАР — ВЕРСИЯ 2

1. В config.js вставьте значения Firebase Web App и databaseURL.
2. Firebase Console → Authentication → Sign-in method:
   включите Email/Password и Anonymous.
3. Authentication → Users → Add user: создайте администратора с EMAIL и ПАРОЛЕМ.
   В config.js замените admin@example.com на этот EMAIL.
   На странице входа логин отображается как obltikpvl, пароль — пароль пользователя Firebase.
   Если хотите пароль 00000, Firebase Authentication может не принять его: минимум 6 символов.
   Используйте более длинный надёжный пароль, например свой уникальный от 12 символов.
4. Authentication → Users: скопируйте UID администратора.
5. Realtime Database → Rules: вставьте содержимое firebase-rules.json,
   заменив REPLACE_WITH_ADMIN_UID на UID администратора, и нажмите Publish.
6. Загрузите ВСЕ файлы index.html, admin.html, display.html, app.js,
   style.css, cases.js, config.js в папку seminar на GitHub Pages.
7. Администратор: /seminar/admin.html; участники: /seminar/;
   LED: /seminar/display.html.
8. При первом входе администратора шесть исходных групп создаются автоматически.

ВАЖНО:
- Пароль 00000 не подходит для стандартной Firebase Email/Password авторизации
  (Firebase требует минимум 6 символов). Не записывайте пароль в JS.
- Правила разрешают анонимному участнику редактировать поле ответа любой группы.
  Номер группы НЕ является надёжной защитой. Для строгого разграничения
  групп нужен отдельный механизм выдачи токенов/привязки пользователей.
- Firebase Realtime Database хранит картинки в формате data URL в записи задания.
  Изображения автоматически уменьшаются; большие изображения могут превысить
  ограничение на размер записи. Для большого количества изображений понадобится
  отдельное хранилище (Firebase Storage либо другое).
- Перед семинаром протестируйте работу на двух разных устройствах и сохранение.
- Поскольку группа не аутентифицирована по номеру, не публикуйте URL для посторонних.
- Старую папку сайта сохраните как резервную копию.
